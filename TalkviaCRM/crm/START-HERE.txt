SHORT TIMEZONE CODES FOR CSV (VERSION 9)
Use EST, CST, MST, PST in the Timezone column. IST is also accepted for India.
Codes are case-insensitive and surrounding spaces are ignored.
EST = US Eastern (New York), CST = US Central (Chicago),
MST = US Mountain (Denver), PST = US Pacific (Los Angeles).
These are region codes for this CRM import: daylight-saving changes are automatic,
not fixed UTC offsets. Mountain here follows Denver, not Arizona.
Existing full IANA names remain accepted. No schema migration is needed.
CSV example header:
Hospital Name,Address,City,State,Phone Number,Timezone
Example timezone cell for California: PST

HOSPITAL-LOCAL SCHEDULING (VERSION 8)
Agents enter callback and demo appointments in the hospital's selected local
IANA timezone. The exact timezone is printed under the field. IST is shown as an
automatic reference conversion, not an input. The admin pipeline also shows local

Upload/replace code files and refresh. No database update for this change.

NORMAL DAILY FLOW
Admin uploads hospital CSV ONCE into a common pool. No agent assignment is needed.
All ready agents automatically receive one eligible, unreserved hospital at a time.
With five agents ready, each receives a different record when opening their workspace.
This is on-demand distribution: the next ready agent receives the next available
record, rather than pre-assigning equal batches or guaranteeing equal daily totals.
Previous/manual ownership does not prevent allocation from the shared pool.
The admin Current / last agent column is for audit, not a manual assignment control.

NON-DUPLICATE ALLOCATION
A short database transaction locks the dispatcher, selects an eligible record that
is not already reserved, sets the agent reservation and records ownership atomically.
A database UNIQUE index independently prevents two active agents reserving the same
lead. An agent also has only one current reservation. Direct links, refresh and
multiple tabs cannot choose a different hospital or overwrite another queue record.

AGENT WORKFLOW
- Log in using the agent's email/password. A lead opens automatically.
- Save details persists contact/status/notes without finishing the call. For email:
  select Interested, Save details, Compose email, review and send.
- Dispose & next hospital logs the call attempt and immediately opens the next
  eligible lead on the same screen. No extra next button or selectable list.
- Choose a status other than New / Not Contacted before disposing.
- Take break pauses allocation; Resume returns to the SAME pending lead.
- Logout marks the user offline. Start work on the next login resumes that lead.
- Save unsaved edits before leaving. A pending reservation is kept over a break or
  logout so another agent does not call the same hospital while it is in progress.
- If no free eligible leads remain, the workspace checks again every 30 seconds.

FOLLOW-UP RULES
Due callbacks/demos take priority over untouched new records. When due, follow-ups
return to the shared pool and may reach a different ready agent; history stays with
that hospital. This is a later scheduled attempt, not simultaneous duplication.
Callback Requested / Follow-up Required: enter a future callback time.
Demo Scheduled: enter a future demo time.
Busy: retry after 30 minutes. No Answer / Voicemail: retry after four hours.
Interested / Information Requested: requeue only when a future callback is supplied;
otherwise hold for sales follow-up, visible to admin.
Do Not Call, Wrong Number, Not Interested, Closed Won and Closed Lost do not requeue.
Admin can update status or scheduled time to reintroduce an eligible record.
No hospital-time calling window is enforced; follow your calling process rules.

ADMIN
Search/filter all hospital records. Hospital name, address, city, state, phone and
timezone are admin-only; agents can edit source/contact/call fields on their current
record. Agent availability shows last recorded mode, reason, current reservation and
recent activity. This is not a live browser-presence monitor. Closing a browser or
losing the network does not automatically mark a user offline or release their lead.
Disable/enable agents and reset passwords using Manage agents. Admin password reset
invalidates previous sessions. Passwords are hashed, not stored as plain text.

IMPORT
CSV UTF-8 columns: Hospital Name,Address,City,State,Phone Number
Optional column: Timezone (IANA value, e.g. America/New_York or Asia/Kolkata).
Download the template from the CRM. Export Excel to CSV UTF-8 before importing;
.xlsx files are not supported directly. Keep phone numbers as text, preserving +
and leading zeros. Limit: 5 MB / 5,000 rows. All five base fields are required.
Same hospital name + phone is skipped as a duplicate. Invalid rows roll back the
complete import. New records join the shared pool without selecting an agent.

TIMEZONES
Admin selects the hospital timezone or supplies it in the CSV; it is never guessed
from the state/city. Existing unspecified zones show Not set. Current hospital-local
time is displayed. Callback/demo inputs use the hospital local timezone, with an
IST equivalent below the field. Data is stored in UTC; date-specific daylight saving is
applied when displaying hospital time.

EMAIL / TELEPHONY
Admin configures the authorised sales mailbox in Email settings. Use SMTP 587 with
STARTTLS or 465 with SSL. Saved passwords are not displayed. Save settings, then test
using a contact/mailbox you control before sending client messages. Each send is
reviewed and confirmed. SMTP acceptance is not guaranteed inbox delivery. Pending or
failed sends require review before retrying; emails are not retried automatically.

Auto-next means automatic RECORD LOADING. This CRM does not dial phone calls or
automatically detect when the conversation ends. Agents call manually, then dispose.

NEW INSTALLATION / CONNECTION RECOVERY
New installation: extract the crm folder under your website root, open /crm/,
provide Hostinger MySQL connection details and create the admin email/password.
Existing database but missing config.php: enter the original database connection
and ORIGINAL admin email/password on setup.php. It restores the connection only
after authenticating that admin; it does not reset users or erase records.
Never use setup to change an existing user's password or create a replacement DB.

REQUIREMENTS / BACKUP
PHP 8.0+ with mysqli/mysqlnd, MySQL/MariaDB with InnoDB, PHP sessions, HTTPS and an
Apache-compatible .htaccess. PHPMailer is bundled; no Composer installation needed.
Back up the database and server-side config.php/mail-config.php privately. Do not
include those passwords in public ZIPs. If the admin password is lost, a hosting
administrator must restore/reset its hash securely; there is no public reset link.
